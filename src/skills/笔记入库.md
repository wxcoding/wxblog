# 笔记入库标准化

把指定的 Markdown 笔记处理成本博客（AstroPaper）可正常构建发布的文章，分两个阶段执行：**先标准化正文，再填充 frontmatter**。顺序固定——description 依据标准化后的正文生成。

核心红线：**只动格式与属性，不动内容**。

## 处理范围

- 用户指定一个或多个 `.md` 文件，或一个目录（处理目录下全部 `.md` 文件）。
- 默认两个阶段按顺序全流程执行；用户明确只要某一阶段（如「只补属性」「只整理格式」）时，只跑对应阶段。
- 逐个文件处理，完成后按文件汇报：正文修复类别与数量、frontmatter 四个字段的值。

## 阶段一：正文标准化（只动正文，不碰 frontmatter）

### 标题层次

- 正文最高层级用 `##`；`#` 一级标题保留给文章题目。若正文首行 `#` 标题与文件名或题目重复，可删除该行；不重复则降级为 `##`。
- 层级递进不跳级：`##` 之后是 `###`，再是 `####`，不出现 `##` 直接跳到 `####`。
- 同一层级的内容使用同一级标题，不随意升降级。
- 统一使用 ATX 风格（`#` 形式），`#` 后跟一个空格，标题前后各留一个空行。
- 标题文字保持原样，不改写、不概括、不增删词。

### 代码

- 代码一律使用围栏代码块并标注语言（如 `java`、`bash`、`yaml`、`xml`、`sql`、`powershell`），不使用缩进式代码块。
- 行内代码、命令、文件路径、配置项、快捷键用反引号包裹。
- 代码块前后各留一个空行。
- 代码块内部的代码内容一律不动（包括注释），只规范围栏与语言标注。

### 强调与行内样式

- 重点词语用 **加粗**，同类关键词的强调风格全文统一。
- 不滥用斜体、删除线；不使用 HTML 标签做样式。

### 列表

- 无序列表统一用 `-`；有序列表用 `1.`、`2.` 连续编号，不与无序混排错乱。
- 嵌套缩进全文统一（每层 2 空格或 4 空格，取其一）。
- 列表与上下文之间留空行；列表项末尾标点风格统一（要么都带句号，要么都不带）。

### 段落与空行

- 段落之间空一行；不出现连续多个空行（最多保留 1 个）。
- 去除行尾多余空格；不用缩进或空行代替标题、列表等结构。

### 中文排版

- 中文与英文、数字之间加半角空格（如「使用 Git 提交」「共 3 章」）。
- 统一使用全角中文标点；专有名词、英文术语的大小写保持原样。

### 其他元素

- 引用块 `>`、表格、分割线 `---` 使用规范；表格列用 `|` 对齐。
- 图片与链接语法完整（`[文字](地址)`），语法残缺的只报告，不擅自补内容。

## 阶段二：frontmatter 填充（只动 frontmatter，不碰正文）

目标格式：

```yaml
---
author: guanwx
pubDatetime: 2021-9-12T13:44:00+08:00
title:
slug:
featured: false
draft: false
tags:
 - Java
description: 。
---
```

填充规则：

1. **pubDatetime** — 在 2022-10-01 至 2023-02-28（即 2023 年 3 月前）之间随机取一个时间。格式严格对照示例 `2021-9-12T13:44:00+08:00`：
   - 年 4 位；月、日不补零（如 `2023-1-8`、`2022-11-2`）
   - 时间为 `HH:mm:00`，小时与分钟两位补零，秒固定为 00
   - 时区固定 `+08:00`
   - 同一批文件不要出现重复时间，可按文件顺序依次取递增的随机时间
2. **title** — 取文件名去掉 `.md` 扩展名后的完整内容，中文原样保留。
3. **slug** — 同样取文件名去扩展名；文件名中的空格替换为连字符。本博客文章 URL 由文件路径生成，slug 仅作参考字段。
4. **description** — 基于阶段一整理后的正文，用简体中文写约 40 字（38–45 字）的摘要，概括笔记核心内容，具体、不套话，以句号结尾。
5. **其他属性保持不变** — author、featured、draft、tags 一律不改动；若文件原本没有 frontmatter，则按目标格式的默认值补齐（author 为 guanwx、featured 为 false、draft 为 false、tags 为 Java）。

## 红线（两阶段通用）

- 不新增内容：不加小节、不加总结、不加示例、不加过渡句。
- 不删除内容：不删段落、不删列表项、不删看似重复的句子。导出杂质（如对话导出的按钮文字「运行」）删除前需向用户确认。
- 不改写内容：不润色措辞、不合并或拆分段落、不调整章节顺序、不改标点语气。
- 阶段一不碰 frontmatter，阶段二不碰正文；已存在的非空字段值不覆盖（包括 description），除非用户明确要求重新生成。
- 拿不准某个改动是否涉及内容取舍时，不改，记录下来向用户确认。
- 不移动、不重命名文件；YAML 值如含特殊字符（冒号、引号等）需按 YAML 规范加引号。

## 工作流程

1. 通读全文，按阶段一检查项记录所有正文问题。
2. 若用户只要质量检查不修复：输出问题清单（位置 + 问题类别 + 修改建议），不改动文件，流程到此为止。
3. 阶段一修复：按「标题 → 代码 → 列表 → 段落空行 → 中文排版」的顺序逐项修复。
4. 阶段二填充：按填充规则补齐 frontmatter。
5. 完成后汇报：正文修复了哪些类别、各多少处；frontmatter 四个字段的值；如有删词、待确认项，一并列出。
